# 実行予算システム DB 更新手順（最新 DB との構造差分の抽出と適用）

方式: SqlPackage（DacFx）で **最新 DB** と **更新先 DB** のスキーマを比較 → 差分 SQL を自動生成 → 更新先 DB に適用
前提: **データ移行は行わない。DB の構造（スキーマ）変更のみ**

> 参照: [`../../課題/DB差分抽出_課題と改善提案.md`](../../課題/DB差分抽出_課題と改善提案.md) の 4-3

## 環境

| 項目 | 値 |
| --- | --- |
| サーバー（Data Source） | `WIN-9L8J6004KJ5\SQLEXPRESS` |
| 最新 DB（比較の**正**・固定） | `ExecutionBudgetDB` |
| 更新先 DB | **作業のたびに入力する** |

> `ExecutionBudgetDB` は発行ファイルを適用済みの基準 DB。
> **新しい発行ファイルを受領したら、まず `ExecutionBudgetDB` を最新化してから本手順を実施する。**

## 全体の流れ

```
  最新DB  ExecutionBudgetDB ──→ source.dacpac ─┐
                                               ├─→ diff.sql ─→ 安全チェック ─→ 更新先DBへ適用 ─→ 検証
  更新先DB （都度入力）      ──→ target.dacpac ─┘
```

所要時間目安: 差分抽出 15〜30 分 / 適用と検証 30 分〜（DB サイズによる）

## 2. 設定値の入力（★PowerShell を開くたびに毎回実行）

**まるごとコピペする。実行すると更新先 DB 名の入力を求められる。**

```powershell
# ============ 設定値 ============
$Server   = "WIN-9L8J6004KJ5\SQLEXPRESS"           # サーバー（固定）
$SourceDb = "ExecutionBudgetDB"                     # 最新DB＝比較の正（固定）
$SqlPkg   = "C:\Tools\SqlPackage\SqlPackage.exe"   # 手順 1 の展開先
# ================================

# ---------- 接続の共通設定 ----------
# SqlServer モジュール v22 以降は接続の暗号化が既定で有効なため、
# 自己署名証明書のローカル SQL Server では証明書の検証に失敗する。
# TrustServerCertificate で回避する（同一サーバー内の接続なので問題ない）。
$SqlArgs = @{ ServerInstance = $Server }        # Invoke-Sqlcmd 用
if ((Get-Command Invoke-Sqlcmd).Parameters.ContainsKey('TrustServerCertificate')) {
    $SqlArgs.TrustServerCertificate = $true
}

# ---------- 認証方式を自動判定 ----------
# ★接続テストは master ではなく「最新DB」に対して行う。
#   サーバーには繋がっても対象DBを開く権限が無いことがあるため。
$SqlAuth = $null
try {
    Invoke-Sqlcmd @SqlArgs -Database $SourceDb -Query "SELECT 1 AS x" -ConnectionTimeout 5 -ErrorAction Stop | Out-Null
    Write-Host "Windows 認証で $SourceDb に接続できました" -ForegroundColor Green
} catch {
    Write-Host "Windows 認証では $SourceDb に接続できません: $($_.Exception.Message)" -ForegroundColor Yellow
    Write-Host "システムの接続文字列に記載されている SQL Server ログインを入力してください" -ForegroundColor Yellow
    $SqlAuth = Get-Credential -Message "SQL Server のログイン情報（例: sa）"
    $SqlArgs.Username = $SqlAuth.UserName
    $SqlArgs.Password = $SqlAuth.GetNetworkCredential().Password
    Invoke-Sqlcmd @SqlArgs -Database $SourceDb -Query "SELECT 1 AS x" -ErrorAction Stop | Out-Null
    Write-Host "SQL 認証で接続できました（$($SqlAuth.UserName)）" -ForegroundColor Green
}

# SqlPackage / sqlcmd 用のパラメータを組み立てる（証明書の警告を回避する指定を含む）
$PkgAuth = @("/SourceTrustServerCertificate:True")   # SqlPackage 用
$CmdAuth = @("-E", "-C")                             # sqlcmd 用（-C = 証明書を信頼）
if ($SqlAuth) {
    $pw = $SqlAuth.GetNetworkCredential().Password
    $PkgAuth += @("/SourceUser:$($SqlAuth.UserName)", "/SourcePassword:$pw")
    $CmdAuth = @("-U", $SqlAuth.UserName, "-P", $pw, "-C")
}

# ---------- 更新先DBを選択・確認 ----------
$ok = $false
do {
    Write-Host "`n--- このサーバー上のデータベース ---" -ForegroundColor Cyan
    Invoke-Sqlcmd @SqlArgs -Query "SELECT name FROM sys.databases WHERE database_id > 4 ORDER BY name" |
        Format-Table -AutoSize

    $TargetDb = (Read-Host "更新先のデータベース名を入力してください").Trim()

    if ([string]::IsNullOrWhiteSpace($TargetDb)) {
        Write-Host "データベース名が入力されていません" -ForegroundColor Red
    }
    elseif (-not (Invoke-Sqlcmd @SqlArgs -Query "SELECT 1 AS x FROM sys.databases WHERE name = N'$TargetDb'")) {
        Write-Host "'$TargetDb' は存在しません。入力し直してください" -ForegroundColor Red
    }
    elseif ($TargetDb -eq $SourceDb) {
        Write-Host "更新先が最新DB（$SourceDb）と同じです。入力し直してください" -ForegroundColor Red
    }
    elseif (-not $(try { Invoke-Sqlcmd @SqlArgs -Database $TargetDb -Query "SELECT 1 AS x" -ErrorAction Stop } catch { $null })) {
        Write-Host "'$TargetDb' を開く権限がありません。別のログインで手順 2 をやり直してください" -ForegroundColor Red
    }
    else {
        Write-Host ""
        Write-Host "  サーバー   : $Server"   -ForegroundColor Cyan
        Write-Host "  最新DB(正) : $SourceDb" -ForegroundColor Cyan
        Write-Host "  更新先DB   : $TargetDb" -ForegroundColor Yellow
        Write-Host ""
        $ok = (Read-Host "この内容で確定します。よろしいですか？ (Y/N)") -match '^[Yy]'
    }
} until ($ok)

# ---------- 作業フォルダを作成 ----------
# このサーバーは C ドライブのみ
$Base    = "C:\dbdiff"
$Version = Get-Date -Format "yyyyMMdd"
$Work    = Join-Path $Base "$($Version)_$TargetDb"
New-Item -ItemType Directory -Force -Path $Work -ErrorAction Stop | Out-Null
Set-Location $Work
Write-Host "作業フォルダ: $Work" -ForegroundColor Cyan
Get-Location
```

> 作業フォルダは `C:\dbdiff\<日付>_<更新先DB名>` に作られる。
> 空き容量は次で確認できる（バックアップを置くため、DB サイズ以上の空きが必要）。
> ```powershell
> Get-PSDrive C | Format-Table Name, @{n='Free(GB)';e={[math]::Round($_.Free/1GB,1)}}, Root
> ```

このブロックが行うこと:

| 処理 | 内容 |
| --- | --- |
| 認証の自動判定 | Windows 認証で接続を試し、失敗した場合のみ SQL 認証のログイン情報を求める。以降のコマンドは認証方式を意識せず同じものが使える |
| DB 一覧の表示 | サーバー上のユーザーデータベースを一覧表示してから入力させる |
| 入力チェック | 存在しない DB 名、最新 DB と同じ名前を弾き、入力し直しさせる |
| **確定の確認** | 内容を表示して `Y` の入力を求める。`N` を押すと入力からやり直す |

> SQL 認証のパスワードは、この PowerShell を閉じるまでの間だけ変数に保持される。作業後はウィンドウを閉じること。

**差分を当てる前に必ず取る。切り戻しの唯一の手段。**

## 5. ② 更新先 DB のスキーマと行数を記録する

```powershell
# --- スキーマを抽出 ---
& $SqlPkg /Action:Extract `
  "/SourceServerName:$Server" `
  "/SourceDatabaseName:$TargetDb" `
  "/TargetFile:$Work\target.dacpac" `
  @PkgAuth `
  /p:ExtractAllTableData=False `
  /p:IgnorePermissions=True `
  /p:IgnoreUserLoginMappings=True

# --- 全テーブルの行数を記録（適用後の検証で使う） ---
$RowCountQuery = @"
SELECT s.name AS schema_name, t.name AS table_name, SUM(p.rows) AS row_count
FROM sys.tables t
JOIN sys.schemas s    ON s.schema_id = t.schema_id
JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0, 1)
GROUP BY s.name, t.name
ORDER BY s.name, t.name;
"@

Invoke-Sqlcmd @SqlArgs -Database $TargetDb -Query $RowCountQuery |
  Export-Csv "$Work\rowcount_before.csv" -NoTypeInformation -Encoding UTF8

Get-ChildItem $Work | Format-Table Name, Length, LastWriteTime
```

`source.dacpac` / `target.dacpac` / `rowcount_before.csv` が揃っていることを確認する。

## 6. ③ 差分 SQL を生成する

`source`（最新 DB＝あるべき姿）を **正** とし、`target`（更新先 DB＝現状）との差分を出力する。

```powershell
& $SqlPkg /Action:Script `
  "/SourceFile:$Work\source.dacpac" `
  "/TargetFile:$Work\target.dacpac" `
  "/TargetDatabaseName:$TargetDb" `
  "/OutputPath:$Work\diff.sql" `
  /p:DropObjectsNotInSource=False `
  /p:BlockOnPossibleDataLoss=True `
  /p:IgnorePermissions=True `
  /p:IgnoreUserSettingsObjects=True `
  /p:IgnoreFileAndLogFilePath=True `
  /p:IgnoreFilegroupPlacement=True `
  /p:ExcludeObjectTypes="Users;Logins;RoleMembership;Permissions;Credentials"

# 中身を確認
notepad "$Work\diff.sql"
```

| オプション | 意味 |
| --- | --- |
| `DropObjectsNotInSource=False` | **更新先 DB にしか無いオブジェクトを削除させない**（最重要の安全弁） |
| `BlockOnPossibleDataLoss=True` | データ損失を伴う変更があれば生成を止める |
| `ExcludeObjectTypes` | ユーザー・権限など環境差のノイズを除外 |

> このコマンドは `.dacpac` ファイル同士の比較のため、DB に接続しない（認証パラメータは不要）。

> **「差分なし」の場合**: 更新先 DB は既に最新の構造。手順 7 以降は不要。
>
> **注意**: この比較では「更新先 DB 固有のカスタマイズ」と「まだ適用していないベンダー変更」を区別できない。
> 更新先 DB にだけ存在する**列**は `DROP COLUMN` として差分に出ることがあるため、次の安全チェックで必ず確認すること。

## 7. ④ 差分 SQL の安全チェック（★必ず実施）

```powershell
$hits = Select-String -Path "$Work\diff.sql" `
  -Pattern 'DROP TABLE|DROP COLUMN|TRUNCATE|tmp_ms_xx|ALTER COLUMN'

if ($hits) {
    Write-Host "要確認の箇所が $($hits.Count) 件あります" -ForegroundColor Yellow
    $hits | Format-Table LineNumber, Line -AutoSize
    $hits | Out-File "$Work\safety_check.txt" -Encoding UTF8
} else {
    Write-Host "危険パターンは検出されませんでした" -ForegroundColor Green
}
```

**検出された場合の判断基準**

| 検出内容 | 判断 |
| --- | --- |
| `DROP TABLE` / `DROP COLUMN` | **要確認**。データが消える。更新先 DB 固有のカスタマイズを消そうとしている可能性が高い。内容を確認するまで適用しない |
| `tmp_ms_xx` を含む | **テーブル再作成**が発生する。大きいテーブルだと長時間ロックされる |
| `ALTER COLUMN`（桁の拡大） | 安全。そのまま進めてよい |
| `ALTER COLUMN`（桁の縮小・型変更） | **要確認**。下記で実データが収まるか確認する |
| `TRUNCATE` | **要確認**。データが消える |

### テーブル再作成（`tmp_ms_xx`）が検出された場合の確認

`tmp_ms_xx` パターンは次の順で実行される。**データは `INSERT ... SELECT` で新テーブルへコピーされる**ため、通常は失われない。

```
① CREATE TABLE tmp_ms_xx_<表名>   … 新しい構造の作業用テーブルを作成
② INSERT INTO tmp_ms_xx_<表名> (列リスト) SELECT ... FROM <表名>   … データを移送
③ DROP TABLE <表名>               … 旧テーブルを削除
④ sp_rename tmp_ms_xx_<表名> → <表名>   … 作業用テーブルを本来の名前に変更
```

**確認すべき点は 2 つ。**

**(1) 更新先 DB にしか無い列が消えないか**
②の列リストに含まれない列は、③の DROP で失われる。次のクエリで列単位の差分を確認する。

```powershell
# 再作成の対象になったテーブル名を指定する
$rebuildTables = @('tbl_tori_GeneralPurpose', 'tbl_tori_Quote')

foreach ($t in $rebuildTables) {
    Write-Host "`n========== $t ==========" -ForegroundColor Cyan
    Invoke-Sqlcmd @SqlArgs -Query @"
WITH s AS (
  SELECT c.name, c.column_id, TYPE_NAME(c.user_type_id) AS type_name, c.max_length, c.is_nullable
  FROM [$SourceDb].sys.columns c
  JOIN [$SourceDb].sys.objects o ON o.object_id = c.object_id
  WHERE o.name = N'$t'
), g AS (
  SELECT c.name, c.column_id, TYPE_NAME(c.user_type_id) AS type_name, c.max_length, c.is_nullable
  FROM [$TargetDb].sys.columns c
  JOIN [$TargetDb].sys.objects o ON o.object_id = c.object_id
  WHERE o.name = N'$t'
)
SELECT COALESCE(s.name, g.name) AS col_name,
       s.column_id AS src_ord, g.column_id AS tgt_ord,
       s.type_name AS src_type, g.type_name AS tgt_type,
       s.max_length AS src_len, g.max_length AS tgt_len,
       CASE WHEN g.name IS NULL              THEN 'ADD (新規追加)'
            WHEN s.name IS NULL              THEN '*** TARGET ONLY (消える) ***'
            WHEN s.type_name <> g.type_name  THEN 'TYPE (型変更)'
            WHEN s.max_length <> g.max_length THEN 'LEN (桁変更)'
            WHEN s.is_nullable <> g.is_nullable THEN 'NULL (可否変更)'
            WHEN s.column_id <> g.column_id  THEN 'POS (位置変更)'
            ELSE '' END AS diff
FROM s FULL OUTER JOIN g ON s.name = g.name
ORDER BY COALESCE(s.column_id, g.column_id);
"@ | Format-Table -AutoSize
}
```

`TARGET ONLY` が出た列は、**更新先 DB 固有の列＝再作成で失われる**。適用前に必ず内容を確認する。
`ADD` / `POS` / `LEN`（桁拡大）だけなら、そのまま進めてよい。

**(2) データ量に対して所要時間が許容できるか**

```powershell
Invoke-Sqlcmd @SqlArgs -Database $TargetDb -Query @"
SELECT t.name AS table_name, SUM(p.rows) AS row_count
FROM sys.tables t
JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0, 1)
WHERE t.name IN ('tbl_tori_GeneralPurpose', 'tbl_tori_Quote')
GROUP BY t.name;
"@ | Format-Table -AutoSize
```

数万件程度なら数秒〜数十秒。数百万件を超える場合はロック時間とログ増加に注意し、業務停止中に実施する。

### `ALTER COLUMN` が検出された場合の確認

**`ALTER COLUMN` が 1 件も無ければ、この確認は不要。** まず該当箇所を一覧する。

```powershell
Select-String -Path "$Work\diff.sql" -Pattern 'ALTER COLUMN' | Format-Table LineNumber, Line -AutoSize
```

桁が**拡大**する変更（`nvarchar(20)` → `nvarchar(50)` など）は安全なのでそのまま進めてよい。
**桁が縮小**する変更（`nvarchar(50)` → `nvarchar(20)` など）だけ、実データが収まるか確認する。

```powershell
# ▼ 下の 3 か所を、実際に検出されたテーブル名・列名・新しい桁数に置き換えて実行する
$tbl = "実際のテーブル名"   # 例: dbo.tbl_tori_Quote
$col = "実際の列名"         # 例: Quote_No
$len = 20                   # 変更後の桁数

Invoke-Sqlcmd @SqlArgs -Database $TargetDb -Query @"
SELECT MAX(LEN([$col])) AS MaxLen, COUNT(*) AS OverCount
FROM $tbl WHERE LEN([$col]) > $len;
"@
```

`OverCount` が 0 でなければ、そのまま適用するとデータが切り捨てられる。**適用せずに相談する。**

**不要な変更を差分から外したい場合** は `diff.sql` を直接編集し、該当の `ALTER` / `DROP` 文を削除してから適用する。

> 判断に迷う場合は `diff.sql` と `safety_check.txt` を AI に読ませて、業務影響・実行順序・切り戻し手順をレビューさせる。

## 8. ⑤ 差分 SQL を更新先 DB に適用する

```powershell
sqlcmd -S $Server -d $TargetDb @CmdAuth -b -i "$Work\diff.sql" -o "$Work\apply_log.txt"
Write-Host "終了コード: $LASTEXITCODE  (0 なら成功)" -ForegroundColor Cyan
notepad "$Work\apply_log.txt"
```

**終了コードが 0 以外の場合は、そこで中断して手順 10 の切り戻しを検討する。**

> **`Invoke-Sqlcmd` ではなく `sqlcmd` を使う理由**: SqlPackage が生成する SQL には `:setvar` や `:on error exit` などの SQLCMD コマンドが含まれるため。
> SSMS で実行する場合は、メニューの **［クエリ］→［SQLCMD モード］** を有効にしてから開くこと。

## 9. ⑥ 適用後の検証

### 9-1. 行数が変わっていないことを確認する（★最重要）

構造変更のみでデータは動かさないため、**行数は適用前と一致するはず**。

```powershell
Invoke-Sqlcmd @SqlArgs -Database $TargetDb -Query $RowCountQuery |
  Export-Csv "$Work\rowcount_after.csv" -NoTypeInformation -Encoding UTF8

$before = Import-Csv "$Work\rowcount_before.csv"
$after  = Import-Csv "$Work\rowcount_after.csv"

$beforeMap = @{}; $before | ForEach-Object { $beforeMap["$($_.schema_name).$($_.table_name)"] = [int]$_.row_count }
$afterMap  = @{}; $after  | ForEach-Object { $afterMap["$($_.schema_name).$($_.table_name)"]  = [int]$_.row_count }

$newTables = @()   # 新規追加テーブル（正常）
$problems  = @()   # 行数が減った / テーブルが消えた（要調査）

foreach ($k in $afterMap.Keys) {
    if (-not $beforeMap.ContainsKey($k)) { $newTables += "$k ($($afterMap[$k]) 件)" }
}
foreach ($k in $beforeMap.Keys) {
    if (-not $afterMap.ContainsKey($k)) {
        $problems += "$k : テーブルが消失（適用前 $($beforeMap[$k]) 件）"
    } elseif ($afterMap[$k] -ne $beforeMap[$k]) {
        $problems += "$k : $($beforeMap[$k]) 件 → $($afterMap[$k]) 件"
    }
}

if ($newTables) {
    Write-Host "`n新規追加されたテーブル（正常）:" -ForegroundColor Cyan
    $newTables | ForEach-Object { Write-Host "  $_" }
}
if ($problems) {
    Write-Host "`n★ 要調査: 既存テーブルの行数が変化しています" -ForegroundColor Red
    $problems | ForEach-Object { Write-Host "  $_" -ForegroundColor Red }
} else {
    Write-Host "`n既存テーブルの行数はすべて一致しています（データ消失なし）" -ForegroundColor Green
}
```

判定の見方:

| 出力 | 意味 |
| --- | --- |
| 新規追加されたテーブル | 今回の更新で追加された表。**正常** |
| 既存テーブルの行数はすべて一致 | **正常。データ消失なし** |
| ★ 要調査 | 既存テーブルの行数が減った、または消えた。**データが失われた可能性があるため調査する** |

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| `SqlPackage : 用語 ... として認識されません` | `$SqlPkg` にフルパス（`C:\Tools\SqlPackage\SqlPackage.exe`）を指定しているか確認 |
| `No .NET SDKs were found.` / `The application 'tool' does not exist.` | `dotnet tool install -g microsoft.sqlpackage` は .NET SDK が必要なため**使わない**。**手順 1-1 の単体版 zip**（`https://aka.ms/sqlpackage-windows`）を使う |
| `Invoke-Sqlcmd : 用語 ... として認識されません` | `Install-Module SqlServer -Scope CurrentUser` を実行 |
| サーバーに接続できない | インスタンス名が `WIN-9L8J6004KJ5\SQLEXPRESS` になっているか確認。`Get-Service MSSQL$SQLEXPRESS` でサービスが起動しているかも確認 |
| Extract 時に権限エラー | 実行アカウントに `db_owner` または `VIEW DEFINITION` 権限が必要 |
| `@PkgAuth` / `@SqlArgs` / `@CmdAuth` が未定義というエラー | 手順 2 を実行していない（PowerShell を開き直した場合も再実行が必要） |
| 認証で `ログインできませんでした` | 手順 2 をもう一度実行し、SQL 認証のログイン情報を入力し直す |
| `このログインで要求されたデータベース "..." を開けません` | サーバーには接続できるが、その DB へのアクセス権が無い。Windows 認証ではなく、システムの接続文字列に記載されている **SQL Server ログイン**（`sa` など）で手順 2 をやり直す |
| `信頼されていない機関によって証明書チェーンが発行されました` / `SSL Provider, error: 0` | 接続の暗号化が既定で有効なため。手順 2 の `TrustServerCertificate` / SqlPackage の `/SourceTrustServerCertificate:True` / sqlcmd の `-C` で回避済み。これらが指定されているか確認する |
| `'' の解析中に無効な構文が見つかりました` | データベース名が未入力のまま Enter を押した。名前を入力し直す |
| 生成された差分が想定より膨大 | 照合順序やユーザー・権限の差を拾っている。`ExcludeObjectTypes` / `Ignore*` オプションを追加する |
| 適用時に `Incorrect syntax near ':'` | SQLCMD モードで実行していない。`sqlcmd -i` を使うか、SSMS の［クエリ］→［SQLCMD モード］を有効にする |
| 適用が終わらない | テーブル再作成が走っている可能性。`sp_who2` でブロッキングを確認 |
| `BACKUP ... WITH COMPRESSION` でエラー | Express は非対応。`COMPRESSION` を外す |
